

\# E-learning Project Instructions



\## Goals

\- Prioritize correctness, security, and maintainability.

\- Preserve existing business rules and application behavior.

\- Follow the project's existing architecture and coding conventions.



\## Repository Exploration

\- Inspect the project structure before making changes.

\- Search for relevant symbols and files before opening large files.

\- Read only the code and documentation needed for the task.

\- Exclude generated files, dependencies, build outputs, and logs unless necessary.

\- Do not repeatedly read files whose contents are already available.



\## Workflow

1\. Identify the relevant code and dependencies.

2\. Explain the root cause or intended change briefly.

3\. Make the smallest complete, correct change.

4\. Run relevant tests and checks.

5\. Report modified files, results, and remaining risks.



\## Safety

\- Do not modify unrelated features.

\- Do not change database schemas, permissions, or business formulas without examining their specifications.

\- Never expose secrets or credentials.

\- Request approval before destructive operations.



\## Efficiency

\- Prefer targeted searches over repository-wide file dumps.

\- Keep tool outputs concise.

\- Avoid unnecessary subagents and repeated commands.

\- Summarize findings rather than pasting entire files.

\- Reuse confirmed findings within the current task.
